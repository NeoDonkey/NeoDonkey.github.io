Updates add. They never remove.

New rule constructions are additive, so rules written years ago keep running unchanged. There is no version of this software that stops reading the previous one.

Two file formats, and that is the whole list.

A company is documents and the transactions that change them. Both are signed commits in a git repository. A format that simple has nothing in it to break.

An older version refuses rather than guesses.

Meet a rule it does not understand and it stops and says so. Silent wrong arithmetic is the one failure an accounting system must never have, so it is designed out.

Update in any order, on any machine.

No maintenance window, no coordinated cutover, no fleet on the same build. Machines on different versions keep working together.

Polyglot outward

Your systems do not need integrating. They need speaking to.

An integration is a project: a scope, a partner, a six figure number and a date it slips past. A dialect is a file. It describes how a foreign system names things, and the runtime reads it. Adding Shopify is not a change request.

Headless

The screen is the disposable part.

Every interface your company uses today will look wrong in ten years, and in most systems the interface and the data are the same object, which is why replacing one means replacing both. Here the core has no screen at all. Interfaces dock on.
