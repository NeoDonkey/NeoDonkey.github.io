NeoDonkey Architecture

How the system is built, and why

The Core Bet

The whole system rests on one claim: a browser, using nothing but web standards, can write a real Git repository with cryptographically verifiable commits.

That claim is proven. Real git — software written by other people over twenty years, which has never heard of NeoDonkey — accepts our output as its own:

$ git fsck --strict
$ git log --show-signature --format='%G? %GS %s'
G sarah@neodonkey.eu goods-receipt GR-0001 created

G is git's own verdict: good signature. That commit was produced by crypto.subtle (Ed25519), CompressionStream('deflate') (zlib, the format git stores), and a fifty-line SHA-1. No libgit2, no isomorphic-git, no npm install.

Kernel

kernel.js is the single entry point. It loads the operating model, validates it against the grammar, and exposes one API to every layer above. There are no exceptions: if a call is not in the kernel's API, it is not possible.

Polism — The Company as Rules

A process is a page of text — prose at the top for humans, rules below for the runtime:

If Create goods-receipt under condition
  quantity > 0 and
  order exists and
  order not already fully delivered
then
  Create goods-receipt-fact and
  Update stock with +quantity and
  Update order-line with status "delivered"

## Authorized by
warehouse-clerk or warehouse-management

When a rule refuses something, it says which sentence refused it, by file and line. When a posting is made, the commit records the rule that authorized it — inside the signed payload.

Live — CRDT + Hybrid Logical Clocks

Multiple machines edit the same company concurrently. Each machine timestamps its commits with an HLC (hybrid logical clock) that captures both wall-clock time and causal ordering. When two commits conflict, the CRDT merge function resolves them deterministically — no consensus protocol, no coordinator, no "last write wins" data loss.

Identity — Ed25519 + SSHSIG

Every actor (person, machine, or process) has an Ed25519 keypair. The private key lives in the browser's WebAuthn/OPFS storage and never leaves the device. The public key is recorded in the repository's organisation/ directory, with roles assigned to it.

Commits are signed with sshsig format, so you can verify them with OpenSSH alone:

ssh-keygen -Y verify -f allowed_signers -I sarah@neodonkey.eu \
           -n git -s commit.sig < commit.canonical
# → Good "git" signature

Read — The View Index

The read layer maintains an index of all documents, their current state, and the relationships between them. It is a cache: it can be rebuilt from the git history at any time. The kernel keeps it consistent, updating it after every verified commit.

Storage — OPFS + Git

The company lives in the browser's Origin Private File System (OPFS) — a persistent filesystem that survives browser restarts and is invisible to other origins. The .git directory is a real git repository, byte-for-byte compatible with what git itself produces.

Zero Dependencies

There is no dependencies field in package.json and there never will be one in the core. Everything is written against:

  • crypto.subtle — cryptography
  • CompressionStream — zlib/deflate
  • TextEncoder — string encoding
  • FileSystemDirectoryHandle — file access
  • WebRTC — peer sync

Standards owned by nobody, stable for decades, only ever extended.

Release Security

The runtime is signed. The signing key is pinned on your machine at first install. Afterwards your installation refuses any runtime not signed by that key — including one served by us, and including one served by us under a court order.

Updates are offered, never applied. The accountant runs version 2 while the warehouse still runs version 1 and both exchange the same facts.
